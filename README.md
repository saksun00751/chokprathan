# โชคประทาน

เว็บหวยออนไลน์ครบระบบ: หน้าแทงพร้อมเครื่องมือใส่เลข โพย ผลรางวัล กระเป๋าเงิน ฝากพร้อมแนบสลิป ถอน แนะนำเพื่อน 2 ชั้น คืนยอดเสีย โปรโมชั่น คูปอง หน้ารวมเกม และหลังบ้านครบชุด มี **ระบบปรับอัตราจ่ายอัตโนมัติ** เมื่อเลขไหนมียอดแทงสูง ตั้งค่าแก้ไขได้ทั้งหมด

หลังบ้านมีแดชบอร์ดพร้อมกราฟ รายงาน 11 แบบที่ดาวน์โหลดเป็น CSV ได้ ระบบสิทธิ์พนักงานตามตำแหน่ง การยืนยันตัวตน 2 ขั้น ธีมสี 5 แบบ และบันทึกการทำงานทุกรายการ

หน้าบ้านและหลังบ้านใช้ได้ 5 ภาษา: ไทย อังกฤษ ลาว พม่า เขมร (ดู [ภาษา](#ภาษา))

สร้างด้วย Next.js 16.4.5 (Cache Components, Partial Prefetching, React Compiler), React 19.3, Tailwind CSS 4 และ MariaDB 10.5 ขึ้นไป (ผ่าน mysql2)

## เริ่มใช้งาน (เครื่องพัฒนา)

ต้องใช้ Node.js 22.13 ขึ้นไป และฐานข้อมูล MariaDB ที่ว่างอยู่

```bash
npm install
cp .env.example .env.local        # ใส่ DATABASE_URL
npm run db -- setup --mode staging --owner admin
npm run db -- seed-demo           # ข้อมูลทดลอง: สมาชิก ประวัติ 4 วัน และงวดที่มียอดแทง
npm run dev
```

ข้อมูลทดลองมีบัญชีสมาชิก `0812345678` รหัส `demo1234` ส่วนรหัสของบัญชีเจ้าของระบบแสดงตอนรัน `setup` ครั้งเดียว ในโหมดทดลอง รหัส OTP แสดงบนหน้าจอ และการฝากเงินอนุมัติทันทีเมื่อกด "ฉันโอนแล้ว"

ติดตั้งใช้งานจริง: ดู [DEPLOY.md](DEPLOY.md)

## ระบบปรับอัตราจ่ายอัตโนมัติ

ระบบนับยอดแทงรวมของทุกคน แยกตามงวด ประเภทการแทง และเลข เมื่อยอดรวมถึงขั้นที่ตั้งไว้ ยอดส่วนที่แทงหลังจากนั้นได้อัตราเป็นเปอร์เซ็นต์ของอัตราปกติ และเมื่อถึงยอดปิดรับเลขนั้นจะไม่รับเพิ่ม ส่วนที่แทงไว้ก่อนยังได้อัตราเดิม

ตัวอย่างค่าเริ่มต้นของ 3 ตัวบน (จ่าย ×950): ยอดรวมถึง ฿2,000 จ่าย 75% (×712.5), ถึง ฿5,000 จ่าย 50% (×475), ถึง ฿10,000 ปิดรับ

- **ค่ากลางทุกหวย:** "อัตราจ่ายและเกณฑ์อั้น" (อัตราจ่าย เกณฑ์แต่ละขั้น ยอดปิดรับ และยอดสูงสุดต่อเลข)
- **เฉพาะหวย:** "ประเภทหวย"
- **อั้นเลขด้วยมือรายงวด:** "งวดและยอดแทง" แล้วเลือกงวด เพื่อดูยอดแทงและยอดที่ต้องจ่ายของแต่ละเลข แล้วกด "จ่ายครึ่ง" "ปิดรับ" หรือกำหนดเปอร์เซ็นต์เอง

ทุกโพยล็อกเลขของตัวเองก่อนคิดอัตรา โพยที่แทงเลขเดียวกันพร้อมกันจึงคิดอัตราต่อกันทีละใบ และไม่มีทางรวมกันเกินยอดปิดรับ ฝั่งสมาชิกเห็นป้าย "อั้น" ในแผงเลขและในโพย หน้าตรวจสอบโพยแสดงอัตราที่ได้จริงของทุกเลข ถ้าอัตราเปลี่ยนระหว่างกดยืนยัน ระบบไม่หักเงินและให้ตรวจอีกครั้ง

## หลังบ้าน

| หน้า | สิทธิ์ที่ใช้ |
|---|---|
| แดชบอร์ด: กำไรจากการแทง ยอดแทง เงินรางวัล ฝากถอน สมาชิกใหม่ ค่ารางวัลสมาชิก เงินสมาชิกในระบบ กราฟรายชั่วโมงหรือรายวัน งวดที่เสี่ยงที่สุด และสถานะระบบ เลือกช่วงวันนี้ ถึงเดือนที่แล้ว หรือกำหนดเอง | `dashboard.view` (ตัวเลขเงินต้อง `reports.view` / `finance.view`) |
| รายงาน: รายวัน แยกหวย รายงวด แยกประเภทการแทง สมาชิก สมัครใหม่ ฝากถอน โปรโมชั่น คืนยอดเสียและค่าแนะนำ การปรับยอด การทำงานของพนักงาน | `reports.view`, ดาวน์โหลด `reports.export` |
| กรอกผลรางวัลหลายงวดพร้อมกัน | `rounds.result` |
| พนักงานและสิทธิ์: เพิ่มพนักงาน ตำแหน่ง ตารางสิทธิ์ ประวัติการเข้าระบบ | `staff.manage` |
| ธีมสี 5 แบบ: ม่วงราชา (เดิม) มรกต ไพลิน ทับทิม อัสดง | `theme.manage` |
| แต้มสะสม: กติกา "ฝากทุก ฿___ ได้ ___ แต้ม" อยู่ที่ตั้งค่าเว็บ (ค่าตั้งต้น ฝาก ฿100 ได้ 1 แต้ม) | `settings.manage` |
| เพิ่ม/ลดแต้มสมาชิกในหน้าสมาชิก (ต้องระบุเหตุผล มีหน้าต่างยืนยัน แต้มไม่ติดลบ) | `members.points` |

**แต้มสะสม** (`src/domain/points.ts`, `src/server/services/points.ts`):
- ได้แต้มเมื่ออนุมัติฝาก และเมื่อพนักงานเติมเครดิตผ่านหลังบ้าน (คิดทีละรายการ ปัดเศษลง: ฝาก ฿150 ได้ 1 แต้ม)
- โบนัสโปรโมชั่น คืนยอดเสีย และค่าแนะนำไม่ได้แต้ม การหักเครดิตไม่หักแต้มคืน (ถ้าต้องการ ให้หักแต้มเองด้วยสิทธิ์ `members.points`)
- ทุกการเปลี่ยนแปลงเก็บในประวัติแต้ม (ตาราง `point_moves`) ยอดคงเหลืออยู่ที่ `member_points` ทั้งสองตารางมากับ migration 5
- สมาชิกเห็นแต้มและประวัติล่าสุดที่หน้ากระเป๋าเงิน และหน้าฝากเงินบอกว่ายอดที่ฝากจะได้กี่แต้ม

ตำแหน่งตั้งต้น: เจ้าของระบบ (ทุกสิทธิ์) ผู้จัดการ การเงิน ดูแลหวย ซัพพอร์ต การตลาด แก้ไขหรือเพิ่มเองได้ เบอร์โทรและเลขบัญชีของสมาชิกแสดงเต็มเฉพาะพนักงานที่มีสิทธิ์ `members.contact` หรือผู้ที่ต้องโอนเงินถอน

## เกม สล็อต คาสิโน กีฬา (AMB SuperAPI)

ต่อกับ [AMB SuperAPI](https://doc.ambsuperapi.com/seamless/introduction.html) แบบ seamless: ค่ายเกมใช้ยอดเงินกระเป๋าหลักของสมาชิกโดยตรง ไม่มีการโอนเงินเข้าออกเกม

- **ตั้งค่า** (ดู `.env.example`): `AMB_API_URL`, `AMB_AGENT`, `AMB_API_KEY`, `AMB_SIGNATURE_KEY` แล้วตั้ง Callback URL ใน AMB Back Office เป็น `<NEXT_PUBLIC_SITE_URL>/api/amb` (หลังบ้านหน้า "เกม สล็อต คาสิโน" แสดง URL นี้ให้) จากนั้นกด "ซิงค์รายการเกม"
- **หน้าเกม** (`/games`): แยกหมวดสล็อต คาสิโน กีฬา อื่นๆ เลือกค่ายแล้วเลือกเกม ระบบขอลิงก์เกมจาก AMB แล้วพาไปเล่น เล่นจบกลับมาที่ `/games` ก่อนซิงค์ครั้งแรกหน้าเกมยังเป็นตัวอย่างเดิม
- **Callback ทั้ง 11 แบบ** (`src/app/api/amb/[action]/route.ts`): checkBalance, placeBets, settleBets, cancelBets, adjustBets, rollback, winRewards, placeTips, cancelTips, voidSettled, adjustBalance
  - กติกาเงินอยู่ใน `src/domain/seamless.ts` และมีเทสต์ครบทุกกรณี
  - ทุก callback ตรวจลายเซ็น HMAC-SHA256 (`AMB_SIGNATURE_KEY`) ไม่มีคีย์นี้ระบบปฏิเสธทั้งหมด จำกัด IP เพิ่มได้ด้วย `AMB_CALLBACK_IPS`
  - ทำในธุรกรรมเดียว ล็อกแถวสมาชิกไว้ callback ที่มาพร้อมกันจึงต่อคิว ส่งซ้ำได้ไม่จ่ายซ้ำ (ตอบ 20002)
  - เลขธุรกรรมของสมาชิกคนหนึ่งไม่มีทางไปแก้ของอีกคน
  - เก็บแยกว่าค่ายรายงานเท่าไร (bet, payout) กับเงินที่ขยับจริง (debited, credited) การคืน ยกเลิกผล หรือ rollback จึงคืนเท่าที่เกิดขึ้นจริง
  - ยอดเงินไม่ติดลบ: ถ้าต้องหักคืนแต่สมาชิกใช้เงินไปแล้ว หักได้เท่าที่มี ส่วนที่เหลือแสดงในหลังบ้าน "ยอดที่หักคืนไม่ได้"
  - สมาชิกที่ถูกระงับ ปิดบัญชี หรือติดบล็อก แทงใหม่ไม่ได้ แต่ผลของตาที่เล่นไปแล้วยังจ่ายตามปกติ
- **ยอดแทงเกม** นับเป็นเทิร์นของโบนัสโปรโมชั่นเหมือนแทงหวย
- **คืนยอดเสียเกม** รายวันในอัตราเดียวกับหวย คิดจากยอดเสียสุทธิของตาที่ออกผลในวันนั้น จ่ายเข้ากระเป๋าคืนยอดเสียหลัง 00:30 (ทิปและการโอนเข้าออกเกมยิงปลาไม่นับ)
- **ประวัติ:** สมาชิกดูได้ที่ `/wallet/games` หลังบ้านดูได้ในหน้าสมาชิก หน้าเกมหลังบ้านมีได้เสียวันนี้และ 7 วันแยกหมวด และเปิด/ปิดแต่ละค่ายได้ (สิทธิ์ `games.manage`)
- **ซิงค์รายการเกม:** ซิงค์เองวันละครั้ง หรือกดเองที่หลังบ้าน
- **ข้อมูล:** ตาราง `game_products`, `game_catalog`, `game_txns`, `game_moves` (ทุกการขยับของยอดเงิน ใช้กระทบยอด), `game_daily`, `game_days` (migration 8)

## กิจกรรมแลกแต้ม

สมาชิกใช้แต้มเล่นลุ้นเครดิตที่หน้า `/activities` (เมนู "แลกแต้มลุ้นเครดิต") ตั้งค่าที่หลังบ้าน "กิจกรรมแลกแต้ม" (สิทธิ์ `promotions.manage`) ทั้งสองเกมติดตั้งมาแบบปิด ต้องกดเปิดเอง

- **วงล้อนำโชค:** ใช้แต้มต่อครั้ง หมุนแล้วได้เครดิตทันที
  - ตั้งรางวัลและโอกาสแต่ละช่องได้ 2 ถึง 12 ช่อง (โอกาสรวมต้อง 100%)
  - ตั้งจำนวนครั้งต่อคนต่อวัน และงบจ่ายต่อวันได้ (งบใกล้หมด รางวัลใหญ่ลดเป็นรางวัลที่ยังจ่ายไหว งบหมดก็หยุดให้หมุน)
  - หน้าตั้งค่าคำนวณให้เห็นว่าเฉลี่ยจ่ายกี่บาทต่อครั้ง และกี่ % ของยอดฝากที่ได้แต้มมา
  - สมาชิกเห็นโอกาสของทุกช่อง
- **ทายเลข 2 ตัวล่าง:** ใช้แต้มต่อเลข ทายงวดที่เปิดอยู่ของหวยที่เลือก
  - ระบบตรวจและจ่ายเองตอนออกผล งวดที่ยกเลิกคืนแต้มให้ ถ้าตรวจไม่สำเร็จ ตัวจัดตารางลองใหม่ให้
  - ตั้งเลขสูงสุดต่อคนต่องวด และงบต่องวดได้ (คนถูกเยอะเกินงบ แบ่งงบเท่ากัน)
- **ผลสุ่มและความปลอดภัย:**
  - ผลสุ่มทำที่เซิร์ฟเวอร์ (crypto) หน้าจอแค่แสดง
  - หักแต้มและจ่ายเครดิตในธุรกรรมเดียว ล็อกยอดแต้มของสมาชิกไว้ กดซ้ำก็ไม่เกินสิทธิ์
  - สมาชิกที่ถูกบล็อกเล่นไม่ได้
- **เครดิตที่ได้:** เข้าเป็นรายการ "รางวัลกิจกรรม" และต้องทำเทิร์นตามที่ตั้ง (ค่าเริ่มต้น 1 เท่า) กันการฝากถอนเพื่อปั่นแต้ม
- **ข้อมูล:** ตาราง `wheel_spins` และ `point_guesses` (migration 7) หน้าตั้งค่ามีสถิติวันนี้และ 7 วัน (ครั้ง แต้มที่ใช้ เครดิตที่จ่าย) และรายชื่อผู้ได้รางวัลล่าสุด

## บล็อกสมาชิก

เมนู "บล็อกสมาชิก" (สิทธิ์ `members.block`, `src/domain/blocklist.ts`, `src/server/services/blocklist.ts`) บล็อกได้ 3 แบบ: บัญชีธนาคาร (ระบุธนาคาร หรือ "ทุกธนาคาร"), เบอร์โทร, และชื่อ-นามสกุล

- **ผลของการบล็อก:**
  - สมัครสมาชิกด้วยข้อมูลนั้นไม่ได้ (เบอร์ที่ถูกบล็อกไม่ได้รับ SMS)
  - สมาชิกที่ตรงกันถูกออกจากระบบทันที และเข้าสู่ระบบใหม่ไม่ได้
  - ถอนเงินไม่ได้ และพนักงานแก้ข้อมูลสมาชิกให้ไปตรงกับรายการบล็อกไม่ได้
- **ข้อความที่ผู้ใช้เห็นไม่บอกว่าติดบล็อกข้อไหน** และการลืมรหัสผ่านทำเหมือนเบอร์ที่ไม่มีในระบบ หน้าเว็บจึงใช้ไล่เช็กรายชื่อที่ถูกบล็อกไม่ได้
- **ชื่อ** เทียบโดยไม่สนคำนำหน้า (นาย นาง นางสาว น.ส. Mr.) ช่องว่าง และตัวพิมพ์เล็กใหญ่ และเทียบทั้งชื่อสมาชิกและชื่อบัญชีธนาคาร **เบอร์** +66 เท่ากับ 0 **เลขบัญชี** ตัดขีดและช่องว่างออก
- **หน้าสมาชิก** มีแถบแดงบอกรายการบล็อกที่ตรงกัน ปุ่มยกเลิกบล็อก และปุ่ม "บล็อกสมาชิกนี้" (เลือกได้ว่าจะบล็อกบัญชี เบอร์ ชื่อ) หน้าฝาก-ถอนมีป้าย "บล็อก" ข้างชื่อ
- **ยกเลิกบล็อกต้องระบุเหตุผล** ประวัติเก็บไว้ (ใคร เมื่อไร ทำไม) และทุกการบล็อกหรือยกเลิกอยู่ในบันทึกการทำงาน ข้อมูลเก็บในตาราง `blocklist` (migration 6)

## ควบคุมการทุจริตในหลังบ้าน

- **ทางเข้าแยกกัน:** พนักงานเข้าระบบที่ `/console` (ชื่อผู้ใช้ รหัสผ่าน และรหัสยืนยัน 2 ขั้นถ้าเปิดไว้) ส่วนสมาชิกเข้าที่ `/login` ด้วยเบอร์มือถือ แต่ละหน้ารับเฉพาะบัญชีของตัวเอง บัญชีที่เข้าผิดหน้าได้ข้อความเดียวกับรหัสผิด session แยกคนละ cookie (`cp_staff` กับ `cp_session`) หน้าลูกค้าจึงไม่เห็นและไม่ลิงก์ไปหลังบ้านเลย เปิด `/admin` โดยไม่มี session พนักงานจะถูกส่งไป `/console`
- **ปรับเครดิตสมาชิก:** ยอดต่ำสุด-สูงสุดต่อครั้งตั้งที่ "ตั้งค่าเว็บ" (ค่าตั้งต้น ฿1 ถึง ฿100,000) ใช้ทั้งเพิ่มและลด ต้องระบุเหตุผลทุกครั้ง ประวัติอยู่ในหน้าสมาชิก (ใคร เท่าไร ยอดก่อน-หลัง เหตุผล)
- **แก้ไขข้อมูลสมาชิก** (ชื่อ เบอร์ บัญชีธนาคาร) ต้องมีสิทธิ์ `members.edit` และระบุเหตุผล เปลี่ยนเบอร์แล้วสมาชิกถูกออกจากระบบ พนักงานที่ไม่มีสิทธิ์ดูเบอร์เต็มจะเห็นช่องว่าง (ไม่เปลี่ยน) แทน
- **ลบสมาชิก = ปิดบัญชี** ต้องมีสิทธิ์ `members.delete` ประวัติเงินและโพยเก็บไว้ครบ ปิดได้เมื่อทุกกระเป๋าเป็น 0 และไม่มีโพย ฝาก หรือถอนค้าง เบอร์และบัญชีธนาคารนั้นสมัครใหม่ไม่ได้ เปิดคืนได้ด้วยสิทธิ์เดียวกัน
- **บันทึกการทำงาน:** เก็บค่าก่อน-หลังแก้ IP เบราว์เซอร์ และทุกครั้งที่มีคนพยายามใช้สิทธิ์ที่ไม่มี ตัวจัดตารางปิดผนึกทุกรายการเป็นสายแฮช (SHA-256) และส่งสำเนาไป MongoDB ทุก 6 ชั่วโมงระบบตรวจทั้งสาย ถ้ามีรายการถูกแก้ ลบ หรือไม่ตรงกับสำเนา หน้า "บันทึกการทำงาน" ขึ้นแถบแดงบอกลำดับที่ผิด
- **บัญชีธนาคารของเว็บ** (เมนู "บัญชีธนาคาร"):
  - **ฝาก:** รายการฝากใหม่ใช้บัญชีรับฝากที่ใช้งานและลำดับแรก อนุมัติฝากแล้วยอดบัญชีนั้นเพิ่มเอง
  - **ถอน:** ตอนกด "โอนแล้ว" พนักงานต้องเลือกบัญชีที่โอนออก ยอดลดเอง
  - **ปรับยอดเอง** (ค่าธรรมเนียม โยกเงินระหว่างบัญชี) ต้องมีสิทธิ์ `banks.adjust` และเหตุผล
  - **เพิ่ม แก้ไข ลบบัญชี** ต้องมีสิทธิ์ `banks.manage` แก้ยอดตรงๆ ไม่ได้ ลบได้เมื่อยอดเป็น 0 และประวัติยังเก็บไว้
  - ยอดติดลบได้และแสดงเป็นสีแดง (ให้ตรวจว่าลืมบันทึกการโยกเงิน) ควรเทียบยอดกับแอปธนาคารเป็นประจำ
- สิทธิ์ใหม่ (`members.edit` `members.delete` `banks.view` `banks.manage` `banks.adjust`) เจ้าของระบบมีครบ ตำแหน่งอื่นต้องติ๊กให้เองที่หน้า "พนักงานและสิทธิ์"
- **ยืนยันก่อนบันทึก:** งานสำคัญทุกอย่างเปิดหน้าต่างสรุปก่อนบันทึกจริง (`src/components/admin/confirm.tsx`) แสดงสิ่งที่จะเกิดขึ้น เช่น ยอดก่อน → หลัง ชื่อสมาชิกและบัญชี เลขผลรางวัลตัวใหญ่ หรือเฉพาะค่าที่แก้ (ก่อน → หลัง) ถ้าไม่มีค่าไหนเปลี่ยนจะไม่บันทึก ปุ่มยกเลิกถูกเลือกไว้ก่อนเสมอ กด Enter ซ้ำจึงไม่ยืนยันเอง ครอบคลุม ปรับเครดิต ระงับ/เปิดบัญชี ตั้งรหัสผ่าน แก้ไข/ปิดบัญชีสมาชิก อนุมัติ/ปฏิเสธฝาก-ถอน (เหตุผลที่ปฏิเสธพิมพ์ในหน้าต่างเดียวกัน) บัญชีธนาคาร (เพิ่ม แก้ ปรับยอด ลบ) ผลรางวัล (ทีละงวดและหลายงวด) ยกเลิกงวด อั้นเลข อัตราจ่ายและเกณฑ์อั้น ตั้งค่าหวย ตั้งค่าเว็บ โปรโมชั่น คูปอง ลบข่าวและแบนเนอร์ พนักงานและสิทธิ์ ปิดการยืนยัน 2 ขั้น และเปลี่ยนธีมสี

## ภาษา

ทุกหน้าของหน้าบ้านและหลังบ้านมีครบ 5 ภาษา: ไทย (`th` ต้นฉบับ) อังกฤษ (`en`) ลาว (`lo`) พม่า (`my`) เขมร (`km`)

- **เลือกภาษา:** ปุ่มรูปโลกที่แถบบนของทุกหน้าและหลังบ้าน ลิงก์ไม่มีรหัสภาษา (`/lotto`) ระบบเลือกภาษาจาก cookie `cp_locale` ถ้าไม่มีดูจากภาษาของเบราว์เซอร์ ถ้าไม่ตรงใช้ภาษาไทย ลิงก์ที่มีรหัสภาษา (`/en/lotto`) ก็ใช้ได้และจำภาษานั้นไว้
- **ข้อความของระบบ** อยู่ใน `src/i18n/locales/<ภาษา>/` แยกเป็นหมวด (`common` `site` `play` `money` `auth` `errors` `admin/*` ...) ภาษาไทยเป็นต้นฉบับ ภาษาอื่นต้องมี key ครบเหมือนกัน แก้คำแปลได้ที่ไฟล์ของภาษานั้นโดยตรง `{n}` `{amount}` คือค่าที่ระบบใส่ให้ และ `[ ]` คือคำที่ไฮไลต์สีทอง ต้องคงไว้ในคำแปล
- **ตรวจอัตโนมัติ:** TypeScript ไม่ยอมให้ build ถ้า key ขาดหรือเกิน และ `src/i18n/locales.test.ts` ตรวจว่าไม่มีข้อความว่าง `{ตัวแปร}` กับ `[ไฮไลต์]` ตรงกับภาษาไทย และหวย เกม แบนเนอร์ โปรโมชั่นตั้งต้นมีชื่อครบทุกภาษา
- **เนื้อหาที่พนักงานแก้** (แบนเนอร์ โปรโมชั่น ข่าวสาร ประกาศหน้าแรก): ฟอร์มหลังบ้านมีแท็บภาษา กรอกภาษาไทยเป็นหลัก ภาษาที่เว้นว่างจะแสดงข้อความภาษาไทยแทน
- **ชื่อหวยและชื่อเกม:** ภาษาไทยใช้ชื่อในฐานข้อมูล (แก้ที่หลังบ้านแล้วเห็นทันที) ภาษาอื่นใช้คำแปลใน `lotto.names` (ตาม slug) และ `info.games` (ตามชื่อภาษาไทย) ถ้าเพิ่มหวยใหม่ที่หลังบ้าน ให้เพิ่มชื่อของภาษาอื่นในไฟล์ `lotto.ts` ของแต่ละภาษาด้วย ไม่เช่นนั้นจะแสดงชื่อภาษาไทย
- **ตัวเลข เงิน วันที่:** ตัวเลขใช้เลขอารบิกรูปแบบ 1,234.50 ทุกภาษา เพื่อให้เลขหวยและยอดเงินอ่านเหมือนกันหมด เงินเป็นบาท (฿) วันที่ใช้ชื่อเดือนของแต่ละภาษา (ภาษาไทยใช้ พ.ศ.) เวลาเป็นเวลาไทยเสมอ
- **ฟอนต์:** ลาว พม่า เขมร ใช้ Noto Sans ของภาษานั้น โหลดเฉพาะหน้าที่เป็นภาษานั้น
- **ข้อมูลที่บันทึกในฐานข้อมูล** เช่น หมายเหตุที่พนักงานพิมพ์ตอนปรับยอด หรือเหตุผลที่ปฏิเสธรายการ จะแสดงตามที่พิมพ์ ไม่แปล หัวตารางของ CSV เป็นภาษาที่พนักงานใช้อยู่ตอนดาวน์โหลด

เพิ่มภาษาใหม่:

1. เพิ่มรหัสภาษาใน `LOCALES` และ `LOCALE_META` ที่ `src/i18n/config.ts`
2. คัดลอก `src/i18n/locales/en` เป็นโฟลเดอร์ของภาษาใหม่ แล้วแปลทุกไฟล์
3. เพิ่มตัวโหลดใน `src/i18n/dictionaries.ts` และคำแปลของแบนเนอร์และโปรโมชั่นตั้งต้นใน `src/server/db/content-i18n.ts`
4. ถ้าเป็นอักษรที่ฟอนต์ไทยไม่มี เพิ่มฟอนต์ใน `src/app/[lang]/layout.tsx`
5. รัน `npm run typecheck` และ `npm test` จนผ่าน

คำแปลภาษาลาว พม่า และเขมร ควรให้เจ้าของภาษาตรวจก่อนเปิดใช้จริง

## MongoDB (สลิป สถิติ log)

MongoDB เก็บเฉพาะข้อมูลที่ไม่ต้องใช้ทรานแซกชันแบบระบบเงิน เงิน บิล เลขในบิล ยอดแทงรายเลข ฝาก-ถอน และสมาชิก อยู่ใน MariaDB เสมอ

| ข้อมูล | ที่เก็บใน MongoDB |
|---|---|
| รูปสลิปและแบนเนอร์ | GridFS bucket `media` |
| สถิติสรุปของแดชบอร์ด รายงาน และหน้าแนะนำเพื่อน | `stats_days` (1 เอกสารต่อวัน) `stats_user_days` (สมาชิกต่อวัน) `stats_rounds` (งวดที่จบแล้ว) |
| ประวัติเข้าระบบ คลิกลิงก์ชวนเพื่อน | `auth_log` (ลบเองเมื่อเกิน 400 วัน) `ref_clicks` |

- สถิติของวันนี้สร้างใหม่ทุก 1 นาทีโดยตัวจัดตารางงวด วันเก่าสร้างใหม่อัตโนมัติเมื่อบิลของวันนั้นออกผล ถูกยกเลิก หรือได้เงินคืน (เช่น บิลหวยรัฐบาลที่แทงล่วงหน้า) ตัวเลขทุกตัวใช้เงื่อนไขเดียวกับก่อนมี MongoDB
- ถ้าไม่ได้ตั้ง `MONGODB_URL` หรือ MongoDB ล่ม ทุกส่วนกลับไปใช้ MariaDB เอง หน้าเว็บไม่พัง แค่ช้าลงเหมือนเดิม
- แอปใช้เฉพาะฐานข้อมูล `MONGODB_DB` (ค่าตั้งต้น `chokprathan`) ไม่แตะฐานอื่นใน cluster
- test ไม่เชื่อม MongoDB จริงเด็ดขาด (ใช้ได้เฉพาะเมื่อตั้ง `TEST_MONGODB_URL` เอง)

## ความปลอดภัย

- รหัสผ่านเก็บแบบ scrypt, session เป็นโทเคนสุ่มที่เก็บเฉพาะค่าแฮช, cookie `__Host-` แบบ httpOnly และ Secure
- พนักงาน: session 12 ชั่วโมง หมดอายุเมื่อไม่ใช้งาน 2 ชั่วโมง ยืนยันตัวตน 2 ขั้นด้วยแอป (TOTP) ต้องเปลี่ยนรหัสผ่านชั่วคราวเมื่อเข้าครั้งแรก
- **ห้าม login ซ้อน (ทั้งสมาชิกและพนักงาน):**
  - บัญชีหนึ่งใช้งานได้ทีละเครื่อง เข้าสู่ระบบเครื่องใหม่แล้วเครื่องเดิมถูกออกทันที (`createSession` ใน `src/server/services/auth.ts`)
  - พนักงานจะไปถึงขั้นนี้ได้ต้องผ่านรหัส 2 ขั้นก่อน คนที่รู้แค่รหัสผ่านจึงเตะเจ้าของบัญชีออกไม่ได้
  - เครื่องเดิมรู้ตัวภายใน 1 นาที (หลังบ้าน 30 วินาที) หรือทันทีที่กลับมาเปิดแท็บ (`SessionWatch` ถาม `/api/session` ซึ่งอ่านอย่างเดียว ไม่ต่ออายุ session) แล้วขึ้นหน้าต่างบอกเหตุผล
  - หน้าเข้าสู่ระบบ (`/login`, `/console`) อธิบายเหตุผลเดียวกัน: เข้าจากเครื่องอื่น, ถูกออกเพื่อความปลอดภัย (เปลี่ยนรหัสผ่าน 2 ขั้น หรือสถานะบัญชี), ไม่ใช้งานนาน
  - หลังบ้านเห็นเวลาและ IP ของเครื่องที่เข้าแทน ทุกครั้งที่เกิดขึ้นบันทึกเป็นเหตุการณ์ "เข้าจากเครื่องใหม่" ในประวัติการเข้าระบบ
  - เหตุผลเก็บในตาราง `session_ends` (migration 4) 35 วัน ก่อน migrate ระบบยังบังคับ 1 เครื่องตามปกติ แต่ข้อความจะเป็นแบบทั่วไป
- **ไม่มีใครให้สิทธิ์เกินตัวเอง** (`canActOnRole`, `mayEditRole` ใน `src/domain/permissions.ts` ตรวจซ้ำที่ `src/server/services/staff.ts`):
  - ตำแหน่งและบัญชีเจ้าของระบบจัดการได้เฉพาะเจ้าของระบบ
  - ผู้ที่มีสิทธิ์จัดการพนักงานให้ตำแหน่งหรือสร้างตำแหน่งได้เฉพาะสิทธิ์ที่ตัวเองมี และแก้ไข ระงับ ตั้งรหัสผ่าน หรือล้าง 2 ขั้นได้เฉพาะคนที่มีสิทธิ์ไม่เกินตัวเอง
  - หน้าจอซ่อนตัวเลือกที่ทำไม่ได้ และเซิร์ฟเวอร์ปฏิเสธเสมอแม้ส่งคำขอตรง
- **บังคับ 2 ขั้นสำหรับพนักงาน** (ตั้งค่าเว็บ): เปิดแล้วพนักงานที่ยังไม่ตั้งค่าใช้ได้เฉพาะหน้า "ความปลอดภัยบัญชี" จนกว่าจะตั้งเสร็จ และปิด 2 ขั้นของตัวเองไม่ได้
- จำกัดความถี่: เข้าสู่ระบบ ขอ OTP สมัครสมาชิก ใส่คูปอง ฝาก ถอน และส่งโพย
- ตรวจสิทธิ์ในตัวดึงข้อมูลและใน Server Action ทุกตัว ไม่พึ่งเมนูหรือ layout
- ทุก query ส่งค่าเป็นพารามิเตอร์ ฐานข้อมูลรันแบบ strict mode และ READ COMMITTED
- รูปที่อัปโหลดตรวจชนิดจากเนื้อไฟล์ สลิปดูได้เฉพาะเจ้าของและพนักงานการเงิน
- Security headers ครบ (CSP, HSTS, frame-ancestors none, nosniff, Referrer-Policy, Permissions-Policy)
- ไฟล์ CSV กันสูตร Excel ที่ฝังมากับข้อความ และการดาวน์โหลดทุกครั้งบันทึกในบันทึกการทำงาน

## โครงสร้าง

```
src/domain           กติกาล้วน: ประเภทการแทง ตัดสินผล คำนวณอัตรา ตารางงวด ช่วงวันที่ สิทธิ์ ธีม (มี test)
src/server/stats     สถิติสรุปใน MongoDB: สร้างจาก MariaDB รวมยอด และงานอัปเดตทุกนาที (มี test)
src/server/db        การเชื่อมต่อ MariaDB, transaction, migration, ข้อมูลตั้งต้น (defaults.ts และคำแปลใน content-i18n.ts) และข้อมูลทดลอง
src/server/services  แทงโพย จ่ายรางวัล ฝาก ถอน คืนยอดเสีย ค่าแนะนำ ยืนยันตัวตน พนักงาน ตัวจัดตารางงวด
src/server/data      ตัวดึงข้อมูลของแต่ละหน้า แดชบอร์ด และรายงาน (ตรวจสิทธิ์ในตัวเอง)
src/server/actions   Server Actions ทุกตัวตรวจสิทธิ์ก่อนแก้ข้อมูล
src/i18n             ภาษา: รายชื่อภาษา ตัวโหลดคำแปล รูปแบบตัวเลขและวันที่ และคำแปลทุกภาษาใน locales/ (มี test)
src/app/[lang]       หน้าเว็บสมาชิก (site), เข้าสู่ระบบ (auth), หลังบ้าน (admin) แยกตามภาษา
scripts              เครื่องมือฐานข้อมูลและ load test
deploy               nginx
```

เงินเก็บเป็นสตางค์แบบจำนวนเต็มทุกจุด อัตราเก็บเป็นอัตรา×100 ทุกการเปลี่ยนยอดเงินเขียนรายการลง `transactions` พร้อมยอดคงเหลือหลังรายการ
