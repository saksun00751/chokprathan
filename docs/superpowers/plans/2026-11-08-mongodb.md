# MongoDB for media, stats, and logs Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Serve dashboard/report/affiliate numbers from pre-built MongoDB summaries and move images and sign-in/referral logs to MongoDB, with MariaDB as the fallback everywhere.

**Architecture:** A per-process `MongoClient` (`src/server/mongo.ts`). Stats are day documents built by SQL that mirrors today's report queries (`src/server/stats/build.ts`), stored and read through an orchestrator with injected dependencies (`store.ts`), summed by pure functions (`derive.ts`), refreshed by a scheduler job (`rollup.ts`). Media uses a GridFS bucket; logs use two collections.

**Tech Stack:** Next.js 16.4.5, TypeScript, mysql2 + MariaDB 10.5, `mongodb` driver 7.8, vitest.

**Spec:** `docs/superpowers/specs/2026-11-08-mongodb-design.md`

## Global Constraints

- Env: `MONGODB_URL`, `MONGODB_DB` (default `chokprathan`). Under vitest MongoDB is off unless `TEST_MONGODB_URL` is set.
- Touch only the app database: no `dropDatabase`, no admin commands except `ping`/`buildInfo`.
- Every MongoDB failure falls back to the MariaDB path; a page never fails because MongoDB is down.
- Status filters: placed = `('pending','won','lost')`; settled = `('won','lost')`. Day = `floor((ms + BKK_OFFSET_MS) / DAY)`; hour slot = `floor((ms - dayStart) / HOUR)`.
- Money stays integer satang; never round in stats.

## Review Focus

1. A Thai government round settles ~16 days after its first bills: the created days must be rebuilt (rollup planner test in Task 4).
2. MongoDB unreachable mid-request: stats come from an in-memory build, media from MariaDB (store test with `db: null` in Task 4; manual check in Task 7).
3. Bills at 23:59:59.999 and 00:00:00.000 Bangkok land on different days (derive test in Task 4).
4. One player active on several days counts once in a range (derive test in Task 4).
5. Today's document older than 3 minutes when the scheduler is not running is rebuilt on read (store test in Task 4).

### Task 2: Images in GridFS

**Files:** Modify `src/server/uploads.ts`, `scripts/db.ts`.

**Interfaces:** Unchanged exports `saveImage`, `readImage`, `removeImage`. New CLI `npm run db -- media-to-mongo`.

- [ ] `saveImage`: GridFS upload (`filename` = name, metadata `{kind, ownerId, mime, size, createdAt}`); on failure or `null` db write the MariaDB row.
- [ ] `readImage`: cache → GridFS (`find({filename})`, download to Buffer) → MariaDB.
- [ ] `removeImage`: delete GridFS files with that filename and the MariaDB row.
- [ ] `media-to-mongo`: for each MariaDB row (batches of 50) upload if missing, verify length, then delete the row; print counts.

**Interfaces:**

- `build.ts`: `buildDay(d): Promise<{ day: DayStats; users: UserDay[] }>`; `buildRound(id): Promise<RoundStats | null>`; `changedDays(sinceMs): Promise<number[]>`; `settledRounds(sinceMs): Promise<number[]>`; `firstDay(): Promise<number | null>`.
- `store.ts`: `getDays(r, now?)`; `userTotals(r)`; `distinctPlayers(r)`; `playersPerLotto(r)`; `playersPerDay(r)`; `downlineSettled(ids)` (`null` when MongoDB is off); `roundStats(r)`; plus `loadDays(deps, ids, now)` (pure orchestration with injected `load/build/save`).
- `rollup.ts`: `rollupStats(now): Promise<void>`; `rebuildAllStats(log): Promise<number>`.

- [ ] Derive tests: day boundary (23:59:59.999 vs 00:00), distinct-player union, zero-filled day and hour buckets, `txSum` wallet filter, `planRollup` includes old created days reported changed and caps work per tick.
- [ ] Store tests (`loadDays`): missing day built and saved; stale today rebuilt; fresh closed day not rebuilt; `load` throwing → everything built, nothing saved.
- [ ] Implement `build.ts` SQL by copying the WHERE/aggregate expressions of `dashboard.ts`/`reports.ts`, bounded to one day; run each query read-only against MariaDB once to prove it parses.
- [ ] Scheduler: `rollupStats` at most every 60 s inside the lock; failures logged, never abort the tick.
